## 1. Что строим

Статический сайт **btsguide.com** для иностранных туристов: как ездить на метро Бангкока.
Деньги — только партнёрские ссылки (Klook, 12Go, Airalo, Agoda, Travelpayouts для RU). Своих продаж, приложения, оплаты, рекламы кафе — **нет и не будет**.

- Языки: **EN** (корень `/`) и **RU** (`/ru/...`, только отобранные страницы). Тайского и китайского UI нет.
- Линии в scope: **BTS Sukhumvit, Silom, Gold; MRT Blue; Airport Rail Link; SRT Red Line только до Don Mueang**. Остальные линии — вне scope.
- Хостинг: **Cloudflare Pages**, Next.js `output: 'export'`. Никакого серверного рантайма, API routes, middleware, ISR.
- Срок проекта до решения о закрытии: **25.01.2027**. Бюджет владельца 6–8 ч/нед — не создавай работу, которую он не успеет проверить.

## 2. Жёсткие запреты (без явного разрешения супервайзера в тексте задачи)

1. **Никаких live-действий:** не пушить в `main`, не деплоить, не трогать DNS/Cloudflare/Namecheap, не регистрироваться в партнёрках, не отправлять формы и письма. Push разрешён только в ветку задачи `task/TNN-...`.
2. **Не выдумывать факты.** Тарифы, номера выходов, время пешком, часы работы, цены билетов, правила оплаты — только из источника (URL + дата) или из заметок Тимы с поездки. Нет источника → `TODO(verify): ...` в тексте и `verified: false` во frontmatter. Страница с `verified: false` получает `noindex` и не попадает в sitemap.
3. **Не генерировать массовые страницы.** Никаких шаблонных страниц «A → B» по парам станций. Новая индексируемая страница появляется только по задаче с конкретным списком slug'ов.
4. **Не добавлять зависимости**, кроме разрешённых: `gray-matter`, `marked`. Остальное — спросить в отчёте.
5. **Не рефакторить вне задачи.** Чинить только то, что названо. Увидел проблему рядом — запиши в отчёт, не трогай.
6. **Не выдумывать партнёрские ID.** Все ссылки идут через `lib/affiliates.ts`; пока ID нет — плейсхолдер `AFFILIATE_ID_PENDING`, ссылка ведёт на обычный URL партнёра без трекинга.
7. Одна сессия = одна задача = одна ветка. Две сессии в одной папке одновременно — запрещено.

## 3. Технические решения (уже приняты, не пересматривать)

- **Маршруты:** EN-страницы в route group `app/(en)/...` с корневым layout `<html lang="en">`; RU — `app/(ru)/ru/...` с `<html lang="ru">`. `hreflang` через `metadata.alternates.languages` только там, где есть пара.
- **Страницы:** `/`, `/fares`, `/fares/2027-joint-fare`, `/tickets-and-cards`, `/airport/[slug]`, `/get-to/[slug]`, `/stations/[code]`, `/where-to-stay-near-bts`, `/sources`, `/about`. Всё через `generateStaticParams` + `generateMetadata`.
- **Контент:** `content/{en,ru}/{guides,airport,stations,pages}/*.md`, frontmatter:
  ```yaml
  title: ""
  description: ""        # ≤155 символов
  slug: ""
  lang: en|ru
  verified: false        # true ставит только Тима/супервайзер
  verified_on: null      # YYYY-MM-DD
  sources: []            # [{url, title, accessed: YYYY-MM-DD}]
  affiliates: []         # ключи из lib/affiliates.ts
  noindex: true          # автоматически true, если verified: false
  ```
- **Тарифы версионируются:** `data/fares/<operator>/<effectiveFrom>.ts`, выбор таблицы через `getFareTable(operator, date)`. Старые таблицы не удалять. До 01.01.2027 поездка через разных операторов = **сумма отдельных тарифов** (пометить в UI). Каждая таблица экспортирует `sources` и `approximate: boolean`.
- **Калькулятор** — клиентский компонент-остров внутри статической страницы. Логика расчёта остаётся в `lib/calculateFare.ts` и покрыта тестами.
- **Партнёрские ссылки:** компонент `<AffiliateLink>` с `rel="sponsored nofollow noopener"`, `target="_blank"`, событие клика в Cloudflare Web Analytics не нужно — достаточно UTM/subid партнёра. Блок раскрытия (`<AffiliateDisclosure>`) на каждой странице с партнёрками.
- **SEO-база:** `app/sitemap.ts` (только индексируемые), `app/robots.ts`, canonical на каждой странице, JSON-LD: `FAQPage` на гайдах, `TrainStation` на станциях. `next/image` с `unoptimized: true`.
- **Вёрстка:** адаптивная (мобильный + десктоп). Тёмная тема остаётся. Никаких анимаций, звуков, переключателей дизайна.
- **Тесты:** `npm test` (node --test). Обязательны для: расчёта тарифа, выбора версии тарифа по дате, sitemap (не содержит noindex-страниц), разбора frontmatter.

## 4. Протокол задачи

**Начало сессии:**
1. `git status` — если дерево грязное, **остановись** и сообщи, ничего не исправляй.
2. `git checkout main && git pull && git checkout -b task/TNN-короткое-имя`.
3. Прочитай задачу в `docs/TASKS.md`. Если критерий приёмки неясен — задай вопрос в отчёте и остановись, не угадывай.

**Во время:**
- Лимит: если задача явно тянет больше ~2 часов работы или требует выйти за scope — остановись и напиши отчёт с предложением, как разрезать.
- Коммиты мелкие, сообщения на английском: `feat|fix|chore|content|data(scope): ...`.

**Конец сессии — обязательно:**
1. `npm run lint && npm test && npm run build` — всё зелёное. Если нет — не скрывай, в отчёт.
2. Обнови статус задачи в `docs/TASKS.md`.
3. Push ветки (не `main`).
4. Выдай отчёт **строго в формате** ниже — его Тима вставит супервайзеру.

```
## Отчёт TNN — <название>
Ветка: task/TNN-...   Коммиты: <hash short> ...
Сделано:
- ...
Файлы: <список изменённых/новых>
Проверки: lint ✅/❌ · test ✅/❌ (N passed) · build ✅/❌ (N pages)
Не проверено / TODO(verify): <список фактов без источника>
Решения, которые я принял сам: <или "нет">
Вопросы супервайзеру: <или "нет">
Время: ~N ч
```

## 5. Definition of Done (для любой задачи)

- Критерии приёмки задачи выполнены дословно.
- lint, test, build зелёные; `out/` собирается без ошибок.
- Нет новых фактов без источника; все `TODO(verify)` перечислены в отчёте.
- Нет изменений вне scope задачи (супервайзер проверяет diff).
- Страница открывается на ширине 375px и 1280px без горизонтального скролла.
